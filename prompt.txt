You are implementing Large File → Summary for Learnova. Ship this in small, testable steps. Ignore databases for now—use temp disk + in-memory state only.

Scope (phase 1)

Accept big files (TXT, PDF, DOCX/DOC).

Extract text, normalize, chunk + map-reduce summarize.

Use existing hf.ts + gemini.ts (with retries) to generate summary.

Add minimal frontend to upload, kick off analyze, poll, and display the summary.

No login/roles/quotas yet. No quiz/flashcards/QA yet.

Backend tasks
1) Endpoints

POST /api/upload

Accept single file field file (TXT, PDF, DOCX, DOC).

Max size: 50 MB (configurable).

Save to temp: /tmp/learnova/<jobId>/<originalName>.

Return { jobId, fileName, mimeType, size }.

POST /api/analyze

Body: { jobId, tasks: ["summary"] } (ignore other tasks for now).

Validate file exists under /tmp/learnova/<jobId>/.

Start an in-memory job (store in a Map: jobs[jobId] = { status, stages, result, error }).

Immediately return { jobId, status: "queued" }.

Spawn async worker (same process) that:

extracting → extract & normalize text (see below)

chunking → chunk + overlap

map_reduce → summarize chunks → reduce to final 3–5 sentence summary

completed → write result to jobs[jobId].result.summary

GET /api/analyze/:jobId

Return { jobId, status, stages, result?, error? }.

stages is an ordered list: ["extracting","chunking","map_reduce","completed"] with timestamps.

2) Extraction

Implement utility extractText(filePath, mimeType):

TXT: UTF-8 read.

PDF: use pdf-parse (or pdfjs-dist)—concatenate pages in order; strip headers/footers if obvious; collapse hyphenated line breaks (some-\nthing → something).

DOCX/DOC: use mammoth (DOCX); for legacy DOC, attempt officeparser or return “unsupported” if not available.

Normalize:

Convert CRLF → LF.

Collapse >2 line breaks to 2.

Collapse multiple spaces.

Drop control chars.

As a final pass, call redactSensitive() from hf.ts.

Edge cases:

Empty or near-empty text ⇒ set job to failed with message “No extractable text”.

Scanned PDF returning no text ⇒ same as above.

Oversized text (e.g., > 1.5M chars) ⇒ we still proceed to chunking; don’t load everything into model at once.

3) Chunking + Map-Reduce summary

Config (env or constants):

CHUNK_SIZE_CHARS=2600

CHUNK_OVERLAP_CHARS=200

Chunk deterministically across characters; ensure overlap (start next chunk at i += CHUNK_SIZE - OVERLAP).

Map step: for each chunk, call summarizeText(chunk, { forceGemini: true }).

If Gemini not configured or fails, hf.ts fallback path will run automatically.

Cap retries via existing logic; log chunk index on error; if one chunk repeatedly fails, skip it and continue.

Reduce step: join all map summaries with \n and call summarizeText(joined, { forceGemini: true }) to produce a final 3–5 sentence summary.

Store the final in jobs[jobId].result.summary.

4) Error handling & progress

Update jobs[jobId].status per stage; push timestamps into stages.

If any stage throws:

Set status="failed", error=humanReadableMessage, keep partial data if available.

Always sanitize HF error messages (don’t leak tokens).

5) Config & limits

Add env with sane defaults (but code should work without them):

UPLOAD_MAX_MB=50

CHUNK_SIZE_CHARS=2600

CHUNK_OVERLAP_CHARS=200

Respect your existing HF/Gemini envs in hf.ts/gemini.ts.
